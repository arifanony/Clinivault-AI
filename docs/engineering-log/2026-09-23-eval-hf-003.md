# Engineering Log: E5 Input-Formatting Normalization (EVAL-HF-003)

- **Date:** 2026-09-23
- **Task:** EVAL-HF-003
- **Author:** Coding Agent

## Objective

Determine whether `intfloat/e5-small-v2`'s benchmark result changes when the
model is evaluated under its **intended** input protocol (`query: ` /
`passage: ` prefixes) instead of the **raw zero-shot** wrapper used in
EVAL-HF-002 — on the same frozen 46-case benchmark, corpus, labels, metrics
and Top-K=5.

## Context

[EVAL-HF-002](./2026-09-22-eval-hf-002.md) recorded `intfloat/e5-small-v2` as the
best local model (MRR **0.5583**, unseating `bge-small-en-v1.5` at 0.5428), and
recorded an explicit limitation alongside that result:

> "E5 models normally mandate `query:` / `passage:` prefixes directly inside
> input prompts, but the test implemented a raw zero-shot wrapper inside
> `HFEmbeddingProvider`."

That left an open question: was the 0.5583 measurement a fair representation of
the model, or an artifact of evaluating it outside its documented protocol?
EVAL-HF-003 exists to close that question before any representation decision
relies on the number.

## Methodology

- `HFEmbeddingProvider` gained **optional** `query_prefix` / `passage_prefix`
  arguments; the defaults (`""`) preserve the historical raw behavior exactly,
  so no prior evidence is invalidated. The provider records the active
  protocol in `provider_params()["input_formatting"]` (`"raw"` or
  `"e5-query-passage"`).
- Two protocols were run over the **same frozen 46 cases** (9 documents) through
  the existing `comparison.run_with_provider()` harness, Top-K=5:

  | Protocol | Query input | Passage input |
  |---|---|---|
  | A. `raw` (EVAL-HF-002 protocol) | `{query}` | `{chunk text}` |
  | B. `e5-query-passage` | `query: {query}` | `passage: {chunk text}` |

- Strictly offline: `local_files_only=True`, CPU only, no network, no API keys.
- Six offline tests cover the prefix surface (`tests/test_comparison.py`,
  `HFInputFormattingTests`), including that raw leaves inputs unprefixed and
  that the E5 prefixes are actually applied to the query and passage inputs.

## Results

| Protocol | Hit@1 | Hit@5 | MRR | CPU wall time |
|---|---|---|---|---|
| A. `raw` (EVAL-HF-002 protocol) | **20/46 (43.5%)** | **36/46 (78.3%)** | **0.5583** | 227.25 s |
| B. `e5-query-passage` | 19/46 (41.3%) | 35/46 (76.1%) | 0.5486 | 210.86 s |

Per-case rank movement (first-relevant rank), protocol B relative to A:
**6 improved, 8 regressed, 32 unchanged**.

Only **three** cases changed Top-5 membership:

| Case | raw | e5-query-passage |
|---|---|---|
| `T2D-005-dka-prevention` | absent (full-rank 6, 7) | rank 5 (improved) |
| `T2D-003-fpg-optimal-cutoff` | rank 5 | absent (full-rank 6) |
| `T2D-003-hba1c-optimal-threshold` | rank 4 | absent (full-rank 13) |

## Cross-checks (protocol integrity)

1. **Harness consistency with EVAL-HF-002:** the `raw` re-run reproduces the
   documented figures *exactly* — Hit@1 20/46, Hit@5 36/46, MRR 0.5583.
2. **Determinism / artifact agreement:** a fresh `raw` re-encode of T2D-001
   (107 chunks, 384-dim) is byte-identical to the persisted EVAL-HF-002 artifact
   `data/embedded-intfloat--e5-small-v2/.../T2D-001.embeddings.json`
   (0 of 107 vectors differ, max absolute difference 0.0).
3. **The protocol switch is real (not a silent no-op):** raw and
   `e5-query-passage` produce different vectors for the same text in 107 of 107
   T2D-001 chunks.

## Findings

- **OBSERVED (FACT):** Normalizing to E5's intended `query:`/`passage:` format
  did **not** improve retrieval on the frozen 46-case benchmark; it produced
  marginally *lower* aggregates on all three metrics (Hit@1 −1, Hit@5 −1,
  MRR −0.0097).
- **OBSERVED (FACT):** The raw zero-shot protocol is deterministic and
  reproducible against the previously persisted EVAL-HF-002 artifacts, so the
  documented 0.5583 is not an artifact of protocol misuse.
- **INFERENCE:** The two protocols differ by amounts close to this benchmark's
  resolution — the entire Hit@5 delta comes from two T2D-003 cases, one of
  which is a one-position near miss (rank 5 → rank 6). The correct reading is
  "protocol normalization did not help", **not** "raw is measurably better than
  the intended protocol".
- **INFERENCE:** Adding the intended prefixes does not change the model
  ranking. `e5-small-v2` remains the best local model measured on this
  benchmark (raw 0.5583 / prefixed 0.5486, both above `bge-small-en-v1.5`
  0.5428, `all-MiniLM-L6-v2` 0.4105, and baseline hash 0.3601).
- **INFERENCE:** The reason prefixing does not help here is not established by
  this experiment; candidate explanations (short clinical noun-phrase queries
  already close to the passage distribution; passage prefixes adding near-
  constant mass; corpus/domain mismatch with E5's pretraining) are untested.
- **NOT YET VALIDATED:** statistical significance of any per-case movement
  (46 cases, single pass); behaviour on other models (BGE/GTE were not
  re-run with normalization); the equivalent normalization question for the
  Gemini semantic provider (which already uses task-typed inputs).

## Conclusion

The EVAL-HF-002 limitation is resolved: the recorded `e5-small-v2` result is
valid under both protocols, and the intended E5 formatting does not improve
retrieval on this benchmark. No production retrieval, embedding, chunking,
Top-K or benchmark-definition code was changed; the only code change is
**evaluation-only** optional prefix support in
`src/clinivault_ai/evaluation/hf_semantic.py` plus offline tests. The
representation comparison remains an evidence record until a formal Decision
Record acts on it.
